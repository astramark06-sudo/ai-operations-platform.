# Security Policy

## Supported versions

Security fixes apply to the current default branch. There is no released application version yet.

## Reporting a vulnerability

Do not publish exploitable vulnerability details, credentials, tokens, or private user data in a public issue.

Use GitHub's **Report a vulnerability** flow in the repository's Security tab when private vulnerability reporting is available. If that option is not enabled, open a minimal public issue asking for a private reporting route without including exploit details.

Include the affected commit or file, impact, reproduction steps that do not expose real secrets, and any suggested mitigation.

## Response expectations

This is a personal project, not a staffed security response team. Reports will be reviewed as availability permits. Do not assume a fixed response or remediation deadline.

## Scope

Only test this repository and systems for which you have explicit authorization. Do not run destructive tests or access other users' data.
